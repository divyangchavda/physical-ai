YOLO-WORLD PERCEPTION EXPERIMENT — CORRECTED IMPLEMENTATION REPORT

CRITICAL FIX:
Initial run used YOLOv8n with COCO vocabulary, NOT YOLO-World with custom vocabulary.
Root causes:
1. Config schema missing `backend` and `vocabulary` fields (Pydantic silently dropped them)
2. CLIP dependency missing (YOLO-World requires OpenAI CLIP, we had open-clip)

After fixing both issues, YOLO-World NOW correctly uses custom vocabulary.

MODEL DETAILS:
================================================================================

Model: yolov8s-world.pt (~44 MB)
CLIP model: ViT-B-32 from open-clip (~605 MB)
Backend: Ultralytics YOLOWorld + open-clip
Device: CPU (PyTorch is CPU-only, CUDA unavailable on this machine)
Vocabulary: Runtime configurable via config.detector.vocabulary

ALTERNATIVE MODELS AVAILABLE:
- yolov8n-world.pt (smaller, faster, lower accuracy)
- yolov8m-world.pt (larger, slower, higher accuracy)
- yolov8l-world.pt (very large, very slow)
- yolov8x-world.pt (extremely large)

Current choice: yolov8s-world for balance of speed/accuracy on CPU.

================================================================================
DETECTION SCHEMA COMPATIBILITY:
================================================================================

YOLOWorldDetector produces IDENTICAL Detection objects:
- detection_id: str (UUID)
- frame_index: int
- timestamp_sec: float
- bbox: BoundingBox (x1, y1, x2, y2)
- class_id: int
- class_name: str
- confidence: float
- source: str ("yolo-world:yolov8s-world")
- is_estimated: bool (True)

S04 (ByteTrack) receives the same schema.
S05-S14 are UNCHANGED.
