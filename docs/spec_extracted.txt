Physical Data Compiler
MVP Technical Specification & Engineering Brief
Role: CTO-level product/architecture specification
Implementation agent: Senior Developer / Claude Code
Status: MVP / Experimental
Primary objective: Validate the core technical thesis before scaling.
1. Vision
We are building a Physical Data Compiler.
Our long-term vision:
Turn messy physical-world video into structured, trustworthy data that robotics and
Physical AI systems can use for training, evaluation, and analysis.
We are NOT initially trying to build:
a humanoid robot
a robotics foundation model
a general-purpose VLM
a robot-control model
a large-scale data-collection company
We are building the data intelligence layer between raw physical-world recordings and robotics AI
systems.
Conceptually:
RAW PHYSICAL-WORLD VIDEO
        ↓
Physical Data Compiler
        ↓
Perception
        ↓
Tracking
        ↓
Temporal Understanding
        ↓
Action Understanding

2. Core Hypothesis
The startup hypothesis is:
Can software turn messy physical video into a structured physical representation that is
accurate enough and cheap enough to be useful?
The first experiment must answer only this question.
We are deliberately NOT attempting to prove that the resulting data can already train a humanoid robot.
That comes later .

10. Component 2 — Frame Sampling
Do NOT initially process every frame.
A 10-minute video at 30 FPS contains approximately:
18,000 frames
Initial sampling:
1 frame / second
Result:
~600 frames
Use these low-frequency frames for initial scene understanding.
If a candidate interaction is detected, process that temporal segment at a higher FPS.
Concept:
10-minute video
      ↓
1 FPS sampling
      ↓
candidate interaction
      ↓
high-resolution temporal analysis
This is critical for keeping compute low.

18. Component 10 — Vision-Language Model
Purpose:
Convert a candidate video segment into semantic physical events.
The VLM should NOT control the whole pipeline.
It answers narrow questions.
Example prompt:
Analyze this physical interaction segment.
Identify:
1. the acting person
2. the relevant hand if visible
3. the objects involved
4. the physical actions
5. approximate action start/end times
6. whether the object state changed
Return ONLY valid JSON using the provided schema.

48. Final Instruction to the Developer
Treat this document as the technical north star for the MVP.
Do not optimize for impressive architecture.
Optimize for:
FASTEST VALID EXPERIMENT
        ↓
MEASURABLE RESULT
        ↓
FAILURE ANALYSIS
        ↓
NEXT TECHNICAL DECISION
The goal is not to prove that we can build a massive Physical AI platform.
The goal is to prove one thing:
Messy physical-world video can be automatically converted into a structured physical
representation with sufficient accuracy and sufficiently low human effort to create
economic value.
If the 10-minute experiment succeeds, we scale.
If it partially succeeds, we identify the bottleneck.
If it fails, we determine exactly why.
Do not hide failures. The failures are the most valuable output of this experiment.
